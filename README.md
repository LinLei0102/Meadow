# 草甸 Meadow · 简体中文版

「Meadow」的正式中文译名定为**草甸**，本仓库是它的简体中文汉化。采用**构建期叠加**的方式实现：仓库根目录的 `index.html`（上游原版）保持原样，中文以独立补丁的形式在构建时注入，产出 `docs/index.html`。

这样做的好处是：上游更新时 `git merge origin/main` 不会产生冲突，重新跑一次构建即可拿到新版中文。

## 直接游玩

下载 [`docs/index.html`](docs/index.html)，用浏览器打开即可（单文件、离线可玩）。

打开后默认**跟随浏览器语言**：中文环境自动进中文，其他环境是英文，可在「设置 → 语言」里随时切换 English / Русский / 简体中文。

## 关于译名

正式译名：**草甸**

- **词义**：草甸是植物学 / 地理学中 meadow 的对应词（与「草原」steppe 相对），指湿润、以多年生草本为主的地段——正是游戏里那片会长草、会下雨、会被淹的地方。
- **区隔**：游戏内已有「草地」一词专指你收割的那片田（`field`，如「位于草地上方时，生长速度翻倍」）。译名用「草甸」，界面里的「草地」不必改动，两个概念不打架。
- **字形**：两字等宽、左右对称，单独做标题不塌；再长的译法（「青青草地」「芳草甸」）在启动页会挤，这个刚好。

译名在三处生效，且都只对中文界面：

| 位置 | 中文 | 英文 / 俄文 |
|---|---|---|
| 窗口标题 | `草甸 Meadow` | `Meadow` |
| 启动页手写标题 | 草甸（两字，草绿 / 露水蓝） | 原版六字母彩色 Meadow |
| 无障碍标签 | 草甸 | 原版 |

标题在源码里是 `<svg><text>` 而不是手绘路径，所以可以换字：两套字形同时存在于 Logo 中，由 `:lang(zh)` 纯 CSS 切换——没有脚本参与，切换语言时不闪烁，英文与俄文玩家看到的仍是原版。

## 完美毕业存档

[`save/perfect.json`](save/perfect.json) 是 0.1.02v 的满级存档，覆盖内测版全部内容。

**怎么用**：双击打开 [`save/import.html`](save/import.html)，点「写入存档 → 打开游戏」，菜单会变成「继续游戏」。只写第 1 号存档位，其他槽位不受影响。

存档内容与依据（数值全部取自源码上限，不是估的）：

| 项 | 存档值 | 依据 |
|---|---|---|
| 通关 | 海洋 `oc = 5e14` | 关卡数组终点 `MS[7]`，界面显示「#10 - 完成」并进入内测版结尾页 |
| 草地升级 | 50 / 90 / 40 / 600 / 180 | `DEFS` 各项 `mx`；基础露水上限是 `60 + 30*ocu2` 的动态值 |
| 水体升级 | 水草 50、露水增益 50 | `WG_MX` / `DG_MX` |
| 廉价升级 | 10 / 10 / 10 / 60 / 20 | `cwb` 表；其中「廉价基础露水」上限是 `5 + 3 + 3*ocu2` |
| 海洋臭氧 | 24 / 4 / 9 / 10 / 1 | 五档升级的硬上限，最高档还要求 `oc ≥ 475000` 且前四档满级 |
| 其它 | 龙卷风 5、空气三叶草 5、雨云 5、露水收获 6、Worldwide Floor 100、露水 Lv15 | 各自上限；Lv15 是 `d10` / `d15` 两个成就的阈值 |

有个细节值得一说：海洋升满后 `ocBase = 0.975 + 0.001*24 + 0.001*1 = 1.0`，`ocK = -ln(1.0)/X = 0`，于是「每立方米减速」的惩罚正好归零——升满臭氧不是把游戏玩死，而是把海洋还原成不减速。这是原作的数值设计，不是修改出来的。

存档是**版本相关**的：上游若改字段，重跑这两条即可再生成并自检。

```bash
node tools/make-save.mjs     # 生成 save/perfect.json + save/import.html
node tools/verify-save.mjs   # 注入浏览器，断言满级 / 通关 / 回写一致
node tools/test-import.mjs   # 端到端验证导入页，并确认不碰其他存档位
```

## 汉化覆盖了哪几层

游戏的语言系统不是一本字典，而是四层，全部覆盖：

| 层 | 覆盖方式 | 规模 |
|---|---|---|
| `T` 字典 + `t()` | 新增 `zh` 语言包 | 185 条 |
| `svT()` / `Q()` 两个文案 helper | 各在函数头部插入中文分支 | 95 + 22 条查表 |
| `cond ? "俄文" : "英文"` 内联三元 | 构建时机械改写成「中文查表，否则回落英文」 | 30 处 |
| `UPD[]` / `SPT[]` 语言数组 | 各加一个 `zh` 数组 | 9 组 + 4 条 |

内联三元那 30 处最容易漏：存档栏位的统计卡、海洋升级面板、海洋描述里的动态数字都藏在这里，只改字典是看不到中文的。构建脚本只认「俄文侧确实含西里尔字母」的三元，俄文分支原样保留，所以 en / ru 行为逐字不变。

漏译是**可测的**，不用靠肉眼：

```bash
node tools/audit-zh.mjs   # 走遍 9 个界面收集可见文本与无障碍名，有漏译退出码 1
```

## 重新构建

```bash
npm install        # 仅首次
npm run build      # 生成 docs/index.html
```

构建脚本的每个补丁点都使用**唯一锚点**。上游一旦改动导致锚点对不上，构建会直接报错并指出是哪一处，不会静默产出半成品。

`i18n/zh.json` 里缺少的键会自动回退英文（而不是显示 `undefined`），所以上游新增文案时可以先构建，再补译。

## 同步上游

```bash
git fetch origin main
git merge origin/main    # 只会更新根目录 index.html，通常无冲突
npm run build            # 重新套用中文补丁
```

## 翻译覆盖面

游戏的语言系统并非集中式字典，而是分散在五处，本项目逐一处理：

| 层面 | 位置 | 处理方式 |
|---|---|---|
| `T` 字典 + `t()` | 主界面 | 注入 `zh` 语言包（185 条） |
| `svT(en, ru)` | 设置 / 存档面板 | 拦截 helper，查表翻译（26 条） |
| `Q(en, r)` | 统计面板 | 拦截 helper，查表翻译（76 条） |
| `SET.lang === "ru" ? … : …` | 内联三元 28 处 | 逐条替换字面量 |
| `UPD` / `SPT` | 更新日志、剧透提示 | 各补一个 `zh` 数组 |

## 已知限制

- 底部导航为纯图标，无文字。
- 内嵌的 Comic Sans 字体子集不含中日韩字形，正文中文回落到系统字体（微软雅黑 / 苹方 / Noto Sans SC）。样式作用域限定在 `:lang(zh)`，不影响英文与俄文的原始观感。
- 启动页标题的两个字形是**固定的**：改译名要同时改 `tools/build.mjs` 里的 `NAME_ZH` / `LOGO_ZH`，并重新用 fontTools 子集出新字（见下）。

## 改译名 / 换字

```bash
# 1. 改 build.mjs 顶部常量
#    NAME_ZH = '草甸'，LOGO_ZH.chars = [['草','#9be04e'], ['甸','#7ec4ee']]
# 2. 重新子集标题字形（需 pip install fonttools brotli）
pip install fonttools brotli
python -m fontTools.subset 你的字体.ttf --text="新译名" --flavor=woff2 \
  --output-file=i18n/fonts/meadow-title-zh.woff2 --no-hinting --desubroutinize
# 3. 重建
npm run build
```

标题字形当前取自[霞鹜文楷](https://github.com/lxgw/LxgwWenKai)（SIL OFL-1.1，允许子集化为 web 字体），许可证见 `i18n/fonts/OFL.txt`。若把字形文件删掉，构建会自动回落到系统黑体并给出提示，不会失败。
